## Вопросы и задания

### 1. Что произошло, когда вы применяли команду `chmod`, чтобы сделать файл исполняемым?
При применении команды `chmod +x` в файле устанавливаются права на исполнение. Благодаря этому ядро Linux и командная оболочка разрешают прямой запуск скрипта как исполняемой программы через `./script_passport.sh`, не требуя вызова интерпретатора по типу `bash script_passport.sh`
### 2. Для каких процессорных архитектур есть готовые дистрибутивы Debian?
Debian предоставляет готовые дистрибутивы для следующий процессорных архитектур: 
1. **`amd64` (x86_64)** — 64-битная архитектура для современных процессоров Intel и AMD
2. **`i386` (x86)** — 32-битная архитектура x86
3. **`arm64` (AArch64)** — 64-битные процессоры ARM
4. **`armhf` (ARM Hard Float)** — 32-битные ARM-процессоры с аппаратной поддержкой чисел с плавающей точкой
5. **`armel` (ARM EABI)** — 32-битные младшие процессоры ARM без аппаратной плавающей точки
6. **`riscv64`** — современная открытая 64-битная архитектура RISC-V
7. **`ppc64el` (POWER / PowerPC)** — 64-битная архитектура IBM PowerPC в режиме little-endian (серверные системы)
8. **`s390x` (IBM Z)** — 64-битная серверная архитектура для мейнфреймов IBM
### 3. Дистрибутив Linux Debian поставляется в нескольких режимах: Netinstall, Live-image, Образа DVD, Cloud. В чем разница этих поставок? Приведите примеры, когда удобно применять каждый из вариантов. Откуда берутся пакеты при установке?
1. **Netinstall** - компактный минимальный ISO-образ (обычно весит 400–700 МБ), содержащий только базовый установщик и минимальный набор утилит для настройки сети и разбивки диска. Netinstall удобно применять, когда на целевом сервере или ПК есть стабильное и быстрое интернет-соединение, а также требуется установить чистую минимальную систему без лишнего предустановленного софта. При использовании Netinstall установщик выкачивает актуальные версии пакетов напрямую из официальных сетевых репозиториев (зеркал) Debian через интернет по протоколам HTTP/HTTPS.
2. **Live-image** - это готовая рабочая система с графической оболочкой, которая загружается напрямую в оперативную память со съёмного носителя без обязательной установки на жёсткий диск. При желании установку на диск можно запустить прямо из запущенной сессии через инсталлятор (например, Calamares). Удобно применять для тестирования совместимости «железа» перед установкой, аварийного восстановления системы (rescue) или временной работы на чужом компьютере без изменения данных на его накопителе. При использовании Live-image базовая система копируется напрямую из сжатого образа файловой системы (SquashFS), находящегося на носителе; недостающие пакеты при наличии сети могут докачиваться из интернета.
3. **Образ DVD** - образ большого объёма (от 4 ГБ и более), в который заранее включены сотни и тысячи пакетов, графические окружения и утилиты. Удобно применять для установки системы на компьютеры и серверы в условиях строгого отсутствия интернета или в изолированных сетевых контурах (air-gapped окружения, закрытые предприятия, удалённые объекты). При использовании DVD-образа большинство пакетов извлекается локально прямо с самого ISO-образа носителя (интернет при установке не обязателен).
4. **Cloud** - готовые преднастроенные образы дисков (в форматах `qcow2`, `raw` и др.), оптимизированные для мгновенного развёртывания в виртуальных средах и облачных провайдерах (OpenStack, AWS, GCP, Proxmox, KVM). Они содержат утилиту инициализации `cloud-init` для автоматической конфигурации при первом запуске (передача SSH-ключей, сетевых параметров). Удобно применять для автоматизированного массового создания виртуальных машин в облаке или CI/CD-пайплайнах через скрипты автоматизации (Terraform, Ansible). При использовании Cloud система уже находится в предустановленном виде внутри образа диска; дополнительные пакеты берутся из зеркал репозиториев Debian через сеть.
