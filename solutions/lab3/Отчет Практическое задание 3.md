## Ответы на контрольные вопросы.
#### 1. Зачем при создании SSH-ключа предлагается задать парольную фразу и от какой угрозы она защищает?
Фраза шифрует закрытый ключ на диске. Если файл ключа украден или скопирован, без фразы им нельзя воспользоваться.
#### 2. Зачем при первом подключении по SSH клиент показывает отпечаток ключа сервера и просит подтвердить его? Что произойдёт, если отпечаток изменится?
Отпечаток позволяет убедиться, что подключение идёт к настоящему серверу, а не к подставному. Если отпечаток изменится, клиент выдаст предупреждение и откажется подключаться: сервер переустановлен или подменён.
#### 3. Если у двух пользователей одинаковые пароли, можно ли понять это по `/etc/shadow`? Почему?
Нельзя. В хеш входит случайная соль, поэтому одинаковые пароли дают разные записи.
#### 4. Таблица атрибутов

| Атрибут | Сокращённое название | Для файла | Для каталога |
| :-- | :-- | :-- | :-- |
| `r` | read | чтение содержимого | просмотр списка имён (`ls`) |
| `w` | write | изменение содержимого | создание, переименование и удаление записей (только вместе с `x`) |
| `x` | execute | запуск как программы | вход в каталог (`cd`) и доступ к файлам по имени |
| `suid` | set user ID | запуск с правами владельца файла | не используется |
| `sgid` | set group ID | запуск с правами группы-владельца | новые файлы наследуют группу каталога |
| `sticky` | sticky bit | не используется | удалять и переименовывать файлы может только их владелец, владелец каталога и root |

#### 5. Почему для удаления файла нужны права на каталог, а не на файл? Какие изменения вносит установка sticky bit на каталог?
Удаление файла — это удаление записи из каталога, то есть изменение каталога (нужны `w` и `x`). Sticky bit разрешает удалять и переименовывать только свои файлы.
#### 6. Приведите команду setfacl, которая даёт конкретному пользователю все права на файл. Как решить с помощью ACL задание 3 из Части 3?
`setfacl -m u:имя:rwx файл`

Задание 3: каталогу выставить права `700` и выдать права через ACL:
`setfacl -m u:u1:rwx /DATA/sec2`
`setfacl -m u:u4:rx,u:u5:rx /DATA/sec2`
#### 7. Чем различаются su, su - и sudo? Почему в Debian для повседневной работы рекомендуют sudo, а не пароль root?
`su` переключает пользователя с паролем целевого пользователя и сохраняет часть окружения, `su -` запускает полный вход с окружением целевого пользователя, `sudo` выполняет одну команду и запрашивает пароль вызвавшего. С sudo пароль root не раздаётся, права выдаются точечно, а каждое использование пишется в журнал.
#### 8. Удалось ли вам обойти ограничение sudo из Части 5, Блок А? Почему правила с подстановочными знаками в sudoers считаются опасными?
Сменить пароль root не удалось. Но правило позволяет сменить пароль любого другого пользователя, например `mtv-1` из группы sudo, и получить root. Знак `*` совпадает с любой строкой, включая пробелы и ключи, поэтому под правило попадают команды, которых автор не предполагал.
#### 9. Чем отличается SIGTERM от SIGKILL? Какой из них процесс может перехватить?
SIGTERM — просьба завершиться, процесс может обработать её и корректно закрыться. SIGKILL убивает процесс принудительно, перехватить его нельзя.
#### 10. Что происходит с процессом, запущенным через &, при закрытии SSH-сессии, и почему nohup меняет это поведение? Почему у процесса с nohup PPID после этого стал другим?
При закрытии терминала оболочка получает SIGHUP и передаёт его заданиям, процесс завершается. `nohup` заставляет процесс игнорировать SIGHUP, и он продолжает работать. Оболочка-родитель завершилась, поэтому процесс усыновляет `systemd` и его PPID становится 1.
#### 11. Что такое зомби-процесс? Можно ли его убить командой kill -9 и почему?
Зомби — завершившийся процесс, код возврата которого ещё не прочитал родитель. Убить его нельзя: он уже завершён, и остаётся только запись в таблице процессов. Она исчезнет, когда родитель прочитает код возврата или завершится.
#### 12. Чем отличается вывод sshd -T от строк, найденных в sshd_config через grep? Приведите пример параметра, у которого они различаются.
`sshd -T` показывает значения, которые сервер реально использует, с учётом `sshd_config.d` и значений по умолчанию, а `grep` только текст файла. Пример: в `sshd_config` было `PermitRootLogin no`, а `sshd -T` показывал `yes` из-за `sshd_config.d/root.conf`.
#### 13. Какой риск возникает, если владельцем исполняемого файла будет root и на этот файл будет установлен suid?
Программа запускается с правами root у любого пользователя. Ошибка в ней или возможность править файлы, как в nano, даёт злоумышленнику полный доступ к системе.
